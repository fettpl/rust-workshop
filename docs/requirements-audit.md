# Zgodność z oryginalnym briefem

Stan po aktualizacji z 12 września 2026. Punktem odniesienia jest pełny tekst przekazany przez użytkownika oraz późniejsze korekty: odbiorca zna podstawy programowania, ale zaczyna Rust od zera; interfejs ma chłodną paletę i większą czytelność.

**Nie wszystkie elementy docelowego kursu są zaimplementowane.** Dostępne są mechaniki produktu oraz 67 lekcji w 18 modułach: 5 lekcji fundamentów Rust, 3 lekcje o pętlach i sterowaniu, 8 pamięci, ownership i podstaw borrowing, 6 modelowania danych, 3 kolekcji, 3 obsługi błędów, 3 rdzenia Todo CLI, 4 modułów i Cargo, 3 formatu pliku, zapisu i terminala, 3 generics, 4 traitów, 3 lifetimes, 3 closures, 4 iteratorów, 3 testowania, 3 Log Analyzer, 3 wartości opakowanych oraz 3 współdzielonej własności. Curriculum obejmuje 70 pojęć, 7 śladów pamięci, 123 wpisy źródłowe i 3 projekty. Najnowszy etap dodaje dziewięć lekcji: pętle, `Box`/`Deref`/`Drop` oraz `Rc`/`RefCell`/`Weak`, w tym ślad życia `Rc`/`Weak`. Dostępna jest część 2 w tym zakresie oraz jednowątkowy zakres części 15; wątki, `Arc`, `Mutex` i async pozostają przyszłe. Zaawansowane Cargo, publiczne API, pozostałe części 15–18, pozostałe pełne projekty i zaawansowana praktyka nadal wymagają pracy. Oryginalny brief sam rozdzielał pierwszy pion produktu od całego curriculum.

„Zaimplementowane” oznacza dostępny kod i ścieżkę użytkownika, a nie potwierdzoną skuteczność uczenia. Wyniki wykonanych kontroli znajdują się w [raporcie weryfikacji](verification.md).

## Mechaniki produktu

| Wymaganie | Stan i dowód |
| --- | --- |
| Local-first, bez logowania, PWA | Zaimplementowane. IndexedDB, lokalne zasoby Monaco i Service Worker; offline działa po pobraniu aplikacji. Wykonanie Rust wymaga sieci. `src/persistence`, `public/sw.js`. |
| Onboarding i diagnostyka przez działanie | Zaimplementowane. Pseudokod, warunek, typ i objaśnione pierwsze ćwiczenie Rust; brak blokowania lekcji. Rekomendacja tempa jest widoczna na dashboardzie. `onboarding.tsx`, `domain/diagnostic.ts`. |
| Profil początkującego w Rust | Zaimplementowane. Nowe sesje zaczynają od `first-program`; zapisane wcześniej sesje zachowują swoją lekcję, kod i ustawienia. Pierwotne porównania do innych języków usunięto zgodnie z późniejszą instrukcją. |
| Dashboard „co teraz?” | Zaimplementowane. Dokładne wznowienie, kroki bieżącej sesji, powtórki, postęp projektu powiązanego z lekcją i pojęcia aktywnego modułu. `components/overview.tsx`. |
| Mapa kursu i kontrakt modułu | Zaimplementowane. Wybór modułu; cel, umiejętności, kryteria wyjścia i związek z projektem. Niezaliczone kryteria prowadzą do konkretnego zadania. Dostęp do lekcji pozostaje otwarty. |
| Graf konceptów i prerekwizytów | Zaimplementowane. Dane i walidacja relacji oraz cykli; czytelny widok powiązań. To lista zależności, nie interaktywny edytor grafu. |
| PREDICT → RUN → OBSERVE → EXPLAIN → MODIFY → DEBUG → RECALL → APPLY | Zaimplementowane jako mechaniki. Obserwacja jest częścią porównania wyniku i wizualizacji, nie zawsze osobnym ekranem. Predykcja wymaga odpowiedzi przed uruchomieniem; walidator odrzuca konfigurację blokującą ten przepływ. Nie każda lekcja zawiera wszystkie etapy. |
| UNDERSTAND → PRACTICE → VERIFY → TRANSFER | Kontrakty i zadania są zaimplementowane. Cele i transfer są dostępne w lekcji; ocenę wspierają wynik programu, testy, przewidywanie i rubric. Jakość modelu mentalnego oraz transferu wymaga pilotażu z uczącym się. |
| Wiele typów ćwiczeń, krótkie lekcje | Zaimplementowane. Przewidywanie, czytanie, modyfikacja, debug, trace, pytania, kolejność, wyjaśnienia, blank-page, testy i assessmenty. |
| Edytor dominujący w zadaniu kodowym | Zaimplementowane. Monaco i dostępny edytor tekstowy, regulacja rozmiaru czcionki, podgląd wyników, mobilne zakładki, Focus Mode. |
| Oryginalny compiler output i Compiler Coach | Zaimplementowane. Zachowany stdout/stderr, strukturalne statusy, dwie progresywne wskazówki i opcjonalne rozwiązanie. Coach jest przygotowaną treścią konkretnego ćwiczenia. |
| Ownership Visualizer | Zaimplementowane. Siedem śladów: move, Copy, clone, współdzielona/mutowalna pożyczka, zakres/drop oraz życie wartości i uchwytów `Rc`/`Weak`; stack/heap i tekstowe wyjaśnienia. Nie jest debuggerem dowolnego kodu użytkownika. |
| Misconceptions | Zaimplementowane w kontrastach, błędnych odpowiedziach i ich objaśnieniach. Po próbie można otworzyć listę częstych błędnych założeń w lekcji. Nie ma automatycznej diagnozy dowolnego własnego wyjaśnienia. |
| Completion oddzielone od mastery | Zaimplementowane. Samo otwarcie czy ukończenie ekranu nie nadaje samodzielności. Silne dowody wymagają niezależnych zadań, a rozumienie także zweryfikowanego kodowania. `engine/learning.ts`. |
| Evidence gates | Zaimplementowane dla dostępnych modułów. Lifetimes, closures i iterators mają niezależne zadania kodowe oraz powtórki; testy sprawdzają relacje zakresów, własność, efekty callbacków i wyczerpanie iteratora. Pętle oraz moduły `Box`/`Deref`/`Drop` i `Rc`/`RefCell`/`Weak` mają po trzy lekcje, świeże alternatywy, testy zachowania i aktywne powtórki. Moduł testowania ma trzy pojęcia, po dwie alternatywy kodowe i kodowe powtórki; ukryty harness sprawdza poprawne oraz wadliwe wskaźniki do funkcji przez `catch_unwind`. Log Analyzer ma trzy lekcje, świeże alternatywy i kodowe powtórki, a tylko główne zadania `records-debug`, `stream-debug` i `report-blank` są oznaczane jako pomoc ujawnionego rozwiązania. Każda para pozostaje dostępna po reveal; kryterium wymaga dowodu z zadania, nie automatycznie obu prób. Rozwiązanie referencyjne pakietu nie zalicza lekcji ani lokalnej checklisty. |
| Poziomy new/exposed/practiced/understood/retained | Zaimplementowane. Utrwalenie wymaga wcześniejszych dowodów i niezależnej poprawnej odpowiedzi po ponad 24 godzinach; samoocena nie zastępuje kodowania. |
| Przekrojowy competency view | Zaimplementowane. Dashboard agreguje pojęcia i unikalne niezależne zadania z wielu lekcji. Poziom kompetencji nie przewyższa najsłabiej potwierdzonego powiązanego pojęcia. `engine/progress.ts`. |
| Retrieval cards i Review Queue | Zaimplementowane. Każde pojęcie ma własną odpowiedź i rozróżnienie, ćwiczenie oraz kolejkę. Oceny Again/Hard/Good/Easy planują powrót. |
| Mieszane aktywne powtórki | Zaimplementowane. Czytanie, przewidywanie, typy, przypadki graniczne oraz naprawy E0382/E0502, kolekcji i Todo z edytorem i testami. Nowe pojęcia generics/traitów dodają siedem kodowych powtórek na innych kontraktach, z dodatkowymi implementacjami i typami bez zbędnych boundów. Kod i wynik są wznawiane; zakończona sesja nie pozwala ponownie naliczać tego samego dowodu. |
| Projekty z kontraktem i retrospektywą | Dostępny wybór trzech projektów: mini-projekt komunikatu Number Guessing, Todo CLI oraz Log Analyzer. Todo ma parser, stan w `Vec`, dwie polityki sesji, format, pliki i terminal; karta udostępnia 11-plikowy pakiet Cargo. Log Analyzer ma trzy lekcje i 10-plikowy pakiet bez zewnętrznych zależności z 19 testami: 11 unit, 5 integration, 2 process CLI i 1 doctest. Startery mają celowe braki, a projekty mają wymagania, ograniczenia, dowody, oddzielne notatki i retrospektywy. Pełne Number Guessing+, Mini grep i capstone pozostają w planie. |
| Blank-page, adversarial inject i scenario assessment | Zaimplementowane w dostępnych modułach. Katalog zawiera 22 zadania blank-page; nowe pętle i smart pointers dodają sześć. Obejmują samodzielny kod, testy granic, zmianę wymagań i rozumowanie. Testy są ukryte w interfejsie, lecz dostępne w źródłach otwartego kursu. |
| Dokładny Resume | Zaimplementowane. Stabilne przestawienie pytań wyboru zachowuje identyfikatory odpowiedzi, ich znaczenie i stan zaznaczenia po reload; zadania porządkowania zachowują własną kolejność. Lekcja, krok, panel, kod, odpowiedzi, próby, pomoc i focus. Karta projektu wznawia jego bieżącą lekcję albo pierwszą nieukończoną, zamiast zawsze kierować do wcześniejszego zadania końcowego. Nowy materiał zachowuje identyfikatory i zapis istniejących sesji. |
| Notatki, bookmarki, export/import | Zaimplementowane. Pełna walidacja importu, potwierdzenie zastąpienia, migracje v1/v2 → v3 bez resetu; odrzucanie nieznanych wersji. |
| Spokojny, czytelny light/dark UI | Zaimplementowana nowa paleta bieli/szarości/granatu z niebieskim akcentem, większa typografia, komfortowe przyciski, przewijana nawigacja i stale dostępna stopka lekcji. Motywy edytora i ikony PWA są spójne. |
| Accessibility | Zaimplementowane podstawy: semantyka, klawiatura, skip link, focus, aria-live, reduced motion, alternatywa Monaco i mobile. Axe i testy klawiatury pokrywają wybrane ścieżki; ręczny test czytnikiem ekranu pozostaje do wykonania. |

## Docelowe curriculum

| Część oryginalnego programu | Pokrycie |
| --- | --- |
| 0 — Setup, Cargo, pierwszy program | Wprowadzenie i ćwiczenia dostępne; instalację wykonuje użytkownik opcjonalnie w swoim terminalu. Aplikacja nie potwierdza jej wykonania. |
| 1 — Zmienne, mutability, scalar types, functions, expressions | Fundamenty dostępne, z naprawami E0384/E0308 i transferem do funkcji. |
| 2 — Control flow | Dostępne są trzy lekcje o `while` z warunkiem i aktualizacją, `loop` z `break` zwracającym wartość oraz wyborze `continue` i etykiet. Zadania używają ograniczonych funkcji liczbowych; szersze algorytmy pozostają rozszerzeniem. |
| 3–4 — Stack, heap, scopes, ownership | Dostępne w module własności. |
| 5 — Borrowing, mutable borrowing, slices | Borrowing i wprowadzenie do slices dostępne. Ćwiczenia obejmują &[i32], &str, pożyczony zakres, granice indeksów i UTF-8; zaawansowane przetwarzanie tekstu pozostaje dalszym materiałem. |
| 6 — Structs, methods, enums, Option, match | Dostępne. Nazwane pola, własny String, impl, &self/&mut self, warianty z danymi, pełny match, Some/None oraz samodzielny model ze zmianą stanu. |
| 7 — Vec/String/HashMap | Dostępne trzy lekcje: operacje i pożyczanie `Vec`, bajty/`char`/granice UTF-8 w `String`, odczyt i aktualizacja `HashMap` przez `entry`. Są zadania i kodowe powtórki; pełne przetwarzanie tekstu i pomiary kosztów pozostają dalszym materiałem; podstawy iteratorów są dostępne osobno. |
| 8 — Result/`?`/panic | Dostępne trzy lekcje: odzyskiwanie kontroli, jawna konwersja błędu parsera na błąd domenowy, propagacja i granica paniki. Etap Todo rozwija błędy IO, rozróżnienie NotFound od uszkodzenia oraz konkretne warianty błędów między parserem, magazynem i aplikacją. Pełne publiczne API błędów pozostaje do rozszerzenia. |
| 9 — Modules/crates/packages | Podstawy zaimplementowane w czterech lekcjach: drzewo i ścieżki modułów, widoczność, prywatny model, importy i re-eksporty oraz granica biblioteki i programu Cargo. Pobierany Todo stosuje układ wielu plików i testy integracyjne. Ćwiczenia inline w przeglądarce nie dowodzą działania osobnych targetów. Zaawansowane Cargo, workspaces, features, publikowanie i polityka MSRV pozostają dalszym materiałem. |
| 10 — Generics | Podstawy dostępne w trzech lekcjach: `T` kontra niezależne `T, U`, funkcje i struktury generyczne, `impl<T>`, odczyt przez pożyczkę, konsumujące `self`, `PartialEq` i `where`. Dwa zadania na pojęcie oraz powtórki sprawdzają również typy bez `Copy`, `Clone` i `Debug`. Publiczne API, pomiary kosztów i użycie w większych bibliotekach pozostają dalszym materiałem. |
| 11 — Traits, associated types i dyn | Podstawy dostępne w czterech lekcjach: własne traity, wymagane i domyślne metody, nadpisania, generyczni konsumenci, `Output` i równość typu powiązanego, statyczny i dynamiczny wybór implementacji oraz pożyczone `&dyn Trait`. Niezależne bramki używają dodatkowych implementacji z testów. Od pustej kartki powstają trait `Measure` z typem powiązanym `Output` i dwoma konsumentami oraz osobna lista reporterów. Wprowadzenie do E0038 nie pokrywa wszystkich reguł zgodności z `dyn`, projektowania API, semver ani kosztów wykonania. |
| 12 — Lifetimes | Dostępne trzy lekcje: problem E0106 przed adnotacjami, niezależne wejścia, struktury pożyczające, elision, E0597/E0515 oraz decyzja owned/borrowed. Variance i HRTB pozostają dalszym zakresem. |
| 13 — Closures i iterators | Dostępne dwa moduły z siedmioma lekcjami: przechwytywanie, move, Fn/FnMut/FnOnce, własność Item, leniwe potoki, short circuit i własne Iterator/IntoIterator. Pomiary kosztów i większe refaktoryzacje pozostają dalszym zakresem. |
| 14 — Testing/rustfmt/Clippy | Podstawowy moduł działa: trzy lekcje o kontraktach asercji, regresjach, unit/integration/doc tests oraz osobnych kontrolach `cargo test`, `cargo fmt` i `cargo clippy`. Property testing, fuzzing, policy CI i pełny code review pozostają dalszym zakresem. |
| 15–17 — Smart pointers, threads, async | Częściowo dostępne. Część 15 ma trzy lekcje `Box`/`Deref`/`Drop` i trzy lekcje `Rc`/`RefCell`/`Weak` oraz ślad `Rc`/`Weak` dla pojedynczego wątku. Wątki, `Arc`, `Mutex` i async pozostają w planie. |
| 18 — Projekty końcowe i projekty spiralne | Częściowe pokrycie. Działa mini-projekt komunikatu Number Guessing, Todo od parsera i sesji do pobieranego pakietu CLI oraz podstawowy Log Analyzer od parsera po deterministyczny raport. Pakiet Log Analyzer ma 10 plików i 19 testów, limit 4096 przechowywanych bajtów linii w pakiecie, CRLF, EOF bez LF, Unicode, duplikaty i błędy IO. Pobranie ani lokalna samoocena nie zaliczają automatycznie lekcji. Pełne Number Guessing+, Mini grep i capstone pozostają do implementacji; benchmarki, property/fuzz i rozszerzony threat model są dalszym zakresem. |

## Rozszerzony cel i granice oceny

Nowy cel obejmuje zaawansowaną praktykę Rust oraz kompetencje potrzebne przy przechodzeniu z mid na seniora. [Mapa zaawansowanego curriculum](advanced-curriculum.md) zachowuje pełne części 0–18 oryginalnego briefu i dodaje publiczne API/semver/MSRV, współbieżność, async z anulowaniem i limitami, profilowanie, unsafe/FFI, testy właściwości, bezpieczeństwo, obserwowalność i analizę incydentów. Dostarczenie treści nie jest równoznaczne z potwierdzeniem poziomu zawodowego. Zapis postępu zachowuje schemat v3 i wcześniejsze identyfikatory lekcji.

Nie przeprowadzono pilotażu z osobą uczącą się. Potrzebne są samodzielna naprawa nowego błędu, wyjaśnienie wyboru i powtórka po ponad dobie. Testy techniczne, walidacja treści i przegląd interfejsu nie zastępują tego dowodu.
